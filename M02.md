7. FLYWAY
==================================================

Integrate Flyway with Spring Boot.

Create the proper migration directory.

Use the standard naming convention:

V1__<description>.sql

There must be ONE authoritative V1 migration.

Do not create duplicate V1 migrations.

The migration must be intentionally minimal and appropriate for the current M02 foundation.

Do NOT create the complete application's future schema during M02.

Do NOT create:

- user authentication tables
- JWT tables
- health profile tables
- food tables
- nutrition tables
- meal-plan tables
- recommendation tables
- budget tables

unless PROJECT_SPEC.md explicitly requires a minimal foundation table for M02.

The purpose of V1 is to prove that Flyway can successfully create and manage the initial database schema.

==================================================
8. JPA CONFIGURATION
==================================================

Configure JPA/Hibernate appropriately for a migration-managed database.

Do NOT use automatic schema creation/update as the source of truth.

Avoid:

spring.jpa.hibernate.ddl-auto=create

or

spring.jpa.hibernate.ddl-auto=update

when that would conflict with Flyway ownership of schema changes.

Flyway must be the authoritative mechanism for schema evolution.

Explain the chosen JPA/Hibernate schema setting in the final report.
